# 铝构 · AlloyFrame

铝型材结构的参数化 3D 预演与算料。中文名突出铝型材结构构建，英文名表达合金框架；技术标识统一为 `alloyframe`。

> 铝型材是金属的榫卯 —— 螺母是榫头，型材槽是卯眼，咬合传力、可拆可调。
> 这个项目给它做参数化算料和 3D 预演。

## 这是什么

一个**标准化的铝型材构建工具**。核心是一条闭环：

```
<数据根>/designs/<id>.json（已保存设计，唯一真相源）
    ├──► 3D 场景（T 槽真实截面 + 拆解视图 + 点选高亮）
    ├──► 算料单（型材下料长度 / 重量 / 估价 / CSV 导出）
    └──► 校验（尺寸一致性 / 引用完整性 / 穿透地面）
```

**一个项目对应一个设计文件**，所有项目共用同一数据根下的型材与配件库。首页 `/` 是项目库，`/projects/<id>` 是按 ID 动态读取的工作台，不再固定打开升降桌。升降桌只是一个示例；可以在页面新建，也可以新增合法的 `designs/<id>.json` 后刷新项目库，不需要改代码。

## 为什么不用通用约束求解器

不做"描述意图 → 求解零件"那一套。那是真正的 CAD 难题，没有尽头。

这里的设计是：**`parts[]` 是完整、显式的零件清单**，3D 和算料都只读它。改尺寸时人（或 Agent）通过表单或 JSON 直接改数字，校验会指出格式、引用和几何不一致；不自动求解结构，也不代替承重或可制造性校核。

引擎是笨的、确定的、无 LLM 的。"智能"全在外面：你可以在编辑器里跟 Agent 对话，让它读 `docs/` 了解领域知识，再修改设计文件并运行 CLI 校验。

## 快速开始

```bash
pnpm install
pnpm dev --hostname 127.0.0.1  # http://127.0.0.1:3000，默认本机使用
pnpm validate                 # 校验当前数据根下 designs/ 中的全部设计
pnpm test                     # 项目存储/API、草稿、校验与 3D 控制回归测试
pnpm typecheck                # TypeScript 检查
pnpm lint                     # ESLint 检查
pnpm build                    # 生产构建
pnpm start --hostname 127.0.0.1 # 启动生产 Node 服务
```

在项目根目录执行。开发与生产默认读取当前工作目录下的 `data/`；需要外部目录时，按下文配置绝对路径。自动化测试不等于浏览器或真机验收。

## 项目库与编辑流程

- **新建 / 复制 / 导入**：首页可搜索名称、说明或 ID，切换进行中与已归档。新建从空零件清单开始；首页复制使用已保存设计，工作台「另存副本」使用当前有效草稿。导入可粘贴 JSON 或读取文件，先校验当前共享库中的引用。三者均生成新的稳定 ID、从 `revision: 0` 开始，不覆盖旧项目；项目文件与写入请求体上限均为 2 MiB。
- **改名 / 归档 / 恢复**：首页重命名直接保存显示名称，不改 ID 或文件名；工作台改名仍按草稿保存流程。归档将原文件移到同一数据根的 `archive/`，不是删除；从首页恢复到 `designs/`，同 ID 已存在时拒绝覆盖。工作台归档前须保存或放弃草稿。坏文件显示「需修复」，不会自动重写，仍可归档或由人 / Agent 修复。
- **表单 → 应用 → 保存**：「零件」可添加、编辑、复制及确认删除构件；「项目」可编辑基础信息和配件清单。表单输入先暂存，点击「添加零件」「应用零件修改」「应用基础信息」或「应用配件清单」才进入项目草稿。**默认开启自动保存**，有效且已应用的草稿停止编辑 1.5 秒后写入服务端正式 JSON；可在独立项目工具栏关闭，或点击「保存」立即写入。尚未应用的输入不进入保存、导出或浏览器备份，且会暂停自动保存。高级 JSON 原文立即进入草稿，允许暂时不完整；有效后才可自动保存。项目 ID 保持不变，修订号由服务端递增。
- **预览与无效草稿**：有效草稿立即驱动 3D 和 BOM（算料），无需先保存；未保存算料会明确标注。JSON 解析、引用或几何校验失败时保留原文和最近有效的 3D 预览，暂停结构化编辑、保存、算料与 JSON / CSV 导出；到「项目 → 高级 JSON」修复。空项目只有警告，可保存后继续添加零件。
- **浏览器备份不是正式数据**：未保存 JSON 草稿尽力备份到当前浏览器、当前来源的 `localStorage`，重新打开时可选择恢复或丢弃，不跨设备同步。它可能因存储禁用、额度或清理而失效。同指纹备份经明确恢复后按当前自动保存设置处理；不同指纹进入冲突暂停。正式项目由连接同一服务的设备共享，重要修改应确认工具栏显示已保存或及时导出。
- **保存中仍可编辑**：自动与手动保存共用一个在途请求。请求提交后的新输入不会被旧响应覆盖；下一次保存使用新的正式文件指纹。无效、未应用、只读、恢复备份待确认、外部冲突或保存失败时不自动写入，失败需手动重试，不会无限循环。离开仅尽力备份 JSON，不承诺卸载时网络保存。自动保存开关只是浏览器偏好，不写入设计。
- **没有历史回滚**：「放弃未保存修改」仅恢复上一次成功保存的文件，不能撤销已自动保存的更改；`revision` 不是历史快照。需要保留版本时导出或另存副本。
- **JSON / CSV 闭环**：「导出 JSON」取得当前有效设计；草稿导出使用 `<id>-draft.json`，不会顺带保存。回首页导入可生成新项目，但 JSON 不包含共享 catalog，目标库必须已有所引用的型材与配件。「算料」导出切割清单 `<id>-cutlist.csv` 和完整算料 `<id>-bom.csv`，来自当前有效草稿并带 UTF-8 BOM；CSV 是下游输出，不能反向导入设计。需要以正式版为准时先保存。

### 文件冲突与 Agent 协作

读取文件时计算原始内容的 SHA-256 指纹；保存、改名、归档、恢复及首页复制会核对所读取的指纹。即使外部 Agent 没有增加 `revision`，内容变化（包括格式化）也会触发 `409` 冲突，而不是仅靠修订号判定。页面在重新获得焦点或「检查文件更新」时检查新版本，不自动替换草稿；有冲突时可确认「载入文件版本」，或将有效草稿「另存副本」 / 导出后手工合并。

同一 Node 进程内、同一数据根的操作串行化，文件更新使用临时文件再替换。**这不是跨进程事务或文件锁**：外部 Agent 与服务同一瞬间写入仍有检查与落盘间的竞争窗口。不要让多个服务实例共写，也应错开 Agent 与页面的写入时段。

### CLI 校验

```bash
pnpm validate standing-desk  # 参数是项目 ID，不是路径；省略则校验全部进行中设计
ALLOYFRAME_DATA_DIR=/srv/alloyframe-data pnpm validate standing-desk
```

CLI 与 UI / API 共用 `inspectDesign`，检查严格 schema、引用、重复零件 ID、按旋转后的包围盒穿地及 `meta.frameHeight` 与模型顶面的偏差；`meta.heightRange` 填写时要求最低值不大于最高值，与表单规则一致；另检查项目 ID 与文件名一致，并打印算料和整体尺寸。只扫描 `designs/`，不扫描 `archive/`；空项目仅警告，退出码 `0` 表示无错误，`1` 表示失败。直接改 JSON 后必须运行校验，再刷新页面；校验通过不代表结构安全认证。

## 数据目录与部署

| 环境变量 | 实际行为 |
|---|---|
| `ALLOYFRAME_DATA_DIR` | 默认为 `<process.cwd()>/data`；显式值**必须是绝对路径**。Web、存储 API 与 CLI 使用同一根目录，其下须有 `catalog/profiles.json`、`catalog/accessories.json`，进行中与归档分别放在 `designs/`、`archive/`。不会只替换 designs 而继续用仓库 catalog。 |
| `ALLOYFRAME_READ_ONLY` | **仅 `1` 启用只读**，`true` 等其他值不会。阻止应用存储层 / API 的全部变更，仍可读取与导出；不限制外部 Agent 的文件系统权限，也不是访问控制。 |
| `ALLOYFRAME_TRUSTED_ORIGINS` | 逗号或空白分隔的完整 `http(s)` 来源（协议、主机及非默认端口），不带路径、尾斜杠或通配符。默认仅允许 loopback 同源写入（`localhost`、`127.*`、`[::1]`，端口须一致）。非 loopback 的目标来源必须列入白名单；写请求须带合法 `Origin`，且与目标同源或也在白名单内。未获写入许可的来源只能查看 / 导出。 |

部署示例（先准备并填充 `/srv/alloyframe-data`；不设置只读开关即允许符合来源规则的写入）：

```bash
ALLOYFRAME_DATA_DIR=/srv/alloyframe-data pnpm build
ALLOYFRAME_DATA_DIR=/srv/alloyframe-data pnpm start --hostname 127.0.0.1
# 只读服务
ALLOYFRAME_DATA_DIR=/srv/alloyframe-data ALLOYFRAME_READ_ONLY=1 pnpm start --hostname 127.0.0.1
```

- **运行形态**：使用单实例、持续运行的 Node 服务和持久文件系统；不是静态导出站点，也不适合临时文件系统或多实例 serverless 共写。数据根与子目录应为真实目录、JSON 为普通文件，不要以符号链接代替；写入需相应权限，`designs/` 与 `archive/` 必须在同一文件系统，归档 / 恢复依赖硬链接。
- **构建与数据分开部署**：外部 data 不会因 `pnpm build` 或应用打包自动随产物携带。部署者必须自行复制或挂载完整数据根、保留数据并安排备份，在构建、启动和 CLI 使用一致配置；不要只发布 `.next` 后期待外部设计和 catalog 自动出现。
- **网络边界**：启动示例显式绑定 loopback；来源保护不会替你限制监听地址。手机 / 平板访问私网服务时，可按实际地址配置如 `ALLOYFRAME_TRUSTED_ORIGINS=http://192.168.254.100:3000`，并限制监听与防火墙范围。**来源白名单不是鉴权**，实现不会确认白名单地址确属私网，非浏览器客户端也可伪造请求头；读取接口亦未鉴权，严禁裸露公网。
- **反向代理**：来源判断使用请求协议与 `Host`，不信任 `X-Forwarded-*`。代理需与实际外部来源 / 协议及白名单一致；公网场景须在外部增加覆盖页面与 API 的鉴权和网络保护，不能仅把公网域名加入白名单。

### 旧名称兼容与迁移

旧部署变量 `SUNMAO_DATA_DIR`、`SUNMAO_READ_ONLY`、`SUNMAO_TRUSTED_ORIGINS` 继续兼容，**对应的新变量已定义时优先，否则读取旧变量，再使用原默认值**。不合并两套来源白名单：新白名单设为空字符串会清空旧配置；新只读值 `0` 会覆盖旧值 `1`，仍只有最终值 `1` 启用只读。显式新数据目录为空或相对路径会报错，不回退到旧目录。

浏览器新键为 `alloyframe:draft:<id>` 和 `alloyframe:autosave`，仅新键不存在时读取旧 `sunmao:draft:<id>`、`sunmao:autosave`。原有关闭自动保存的偏好继续生效；草稿仍须明确选择恢复，不会自动载入或写入正式文件。成功写入新键后才清理旧键，写入失败保留旧数据；采用文件或丢弃备份会清理双键，防止旧草稿重新出现。兼容仅限同一浏览器、同一来源，改域名或端口不会迁移浏览器存储。

本地项目目录与包名统一为 `alloyframe`。更名不修改设计 ID、JSON 格式、数据内容、Git 历史或远端地址，也不自动移动外部数据目录；已有绝对路径可继续使用。以上路径仅为新部署示例。

## 手机、平板与桌面

以下为项目工作台的布局与视图操作。

- **手机 / 平板竖屏（< 1024px）**：上方是全宽 3D，下方为可独立滚动的零件 / 算料 / 项目面板。点击「收起面板」可给 3D 更多空间。
- **手机短屏横向（≥ 640px 且高度 ≤ 540px）**与桌面：使用左右布局，侧面板同样可以收起。
- **3D 直接操作**：鼠标左键拖动旋转、滚轮 / 中键拖动缩放、右键或 Shift + 左键拖动平移；触屏单指旋转、双指捏合缩放 / 同向移动平移，轻点选择零件。触控板可按住点击拖动、双指滚动缩放、Shift + 点击拖动平移，捏合取决于浏览器是否转换为缩放事件。无需切换控制模式，以上操作只改变视图，不修改设计中的毫米尺寸。面板滚动和拆解工具条不影响 3D 视角。
- **坐标与视角**：右手坐标，地面中心为原点，X 向右、Y 向上、Z 朝正面，单位 mm。右上方向指示随相机旋转；「视角」提供正视（从 +Z）、右视（从 +X）、顶视（从 +Y，屏幕上方为 −Z）。「适应视图」居中并保留观察方向；「重置视角」恢复默认斜视；「全屏」针对画布和视图工具栏，可按 Esc 退出。不支持或拒绝时不会冒充成功。
- **拆解 / 装配**：点「拆解」直接到 100%，点「装配」回到 0%。「调整分离程度」展开滑杆，可用方向键、Home / End 微调。百分比是展示位移的程度，不是拆装步骤的进度；视角重置不改变它。算法依据位置、尺寸、类型及角色关键词同时展开，不包含连接拓扑、碰撞检测或拆装工序，不保证任何项目都能完全分离或真实可拆。不同项目可能需要专门方向、分组和阶段方案，当前没有这类配置。
- **选中详情**：与零件列表放在同一个滚动面板，不遮挡窄屏模型；点击关闭按钮或空白画布取消选择。
- **状态保留**：横竖屏切换、面板收起、零件 / 算料 / 项目切换不会重建 Canvas，也不清空拆解值和选中项。
- **界面职责**：顶栏仅导航与系统外观；独立项目工具栏提供保存、自动保存状态及「⋯」文件操作；画布工具栏只改变视图与拆解展示。归档、放弃等低频操作在项目面板，不与主题混排。手机采用紧凑分组和弹层，不要求横向滚动工具栏。
- **主题**：首次默认跟随系统，顶栏可选择浅色 / 深色；明确偏好继续保留。画布、网格、方向标签、选中色和材料列表同步适配，保留材料语义和用户页面缩放；主题不写入设计，不改变算料。

首次载入与「适应视图」根据实际画布宽高比拟合装配和最大拆解的联合边界；横竖屏、窗口尺寸和面板开关只调整适配距离，保留用户平移目标、观察方向和相对缩放比例。手动放大后允许局部出框，点击「适应视图」即可重新居中；不会悄悄覆盖手动视角。静止场景按需渲染，小屏降低 DPR 和阴影分辨率，使用同一套模型和材料。

布局已包含动态视口高度和安全区边距。内置浏览器的尺寸检查不能替代 iOS / Android 真机的多指手势、浏览器地址栏 / 刘海安全区及 Safari 下载测试。触控板捏合与双指抬起一指后的手势衔接也需实机检查；当前控件的双指手势结束后，若剩余单指未接续旋转，重新按下即可继续。

已在隔离数据的生产预览中检查 320×568、390×844、844×390、768×1024 和 1440×900 的工作台、手机项目库与深浅主题，没有观测到页面横向溢出；走通新建空项目、零件添加、元信息与配件编辑、保存刷新、粘贴 JSON 导入、项目复制改名、归档恢复、无效 JSON 原文与算料隔离、草稿恢复，以及外部同修订号变更检测、另存副本和重新载入。内置浏览器未能捕获 JSON 下载事件，因此文件下载与导出后再导入的完整 GUI 往返仍待验证；文件选择上传在该环境不受支持。自动测试覆盖 JSON 往返与 CSV 数据规则，但不能替代浏览器落盘、真机多指手势、Safari 下载和帧率 / 功耗验收。

本轮在隔离数据的生产预览中复验上述五种尺寸和浅 / 深主题，检查坐标方向指示、分层工具栏、一键拆解与正视切换；验证未应用表单不落盘、应用后的有效草稿自动写入 JSON 并在刷新后保留、无效 JSON 暂停，以及外部同修订号修改触发冲突、有效本地草稿不覆盖外部文件和明确载入后解除暂停。自动测试覆盖保存期间的新原文/表单、指纹推进、防抖与手动去重、失败暂停和迟到读取。内置浏览器的全屏请求被拒绝，失败提示已验收；实际成功全屏、Esc 退出和全屏内弹层仍需支持该能力的浏览器验证。浏览器定位点击在本环境出现超时，部分页签和表单操作通过已观察节点或页面 DOM 触发完成，不等同于完整真人输入 E2E。

品牌更名后在隔离数据的生产预览中检查项目库、工作台、浏览器标题和保存说明，确认统一使用“铝构 · AlloyFrame”；320×568 的工作台没有观测到横向溢出。验证旧自动保存关闭偏好继续生效、旧草稿须明确恢复、无效原文不落盘、成功写入新键后清理旧键，以及采用已保存文件时清理双键。此验收中的恢复、开关和管理操作由已观察的页面 DOM 触发，不等同于完整真人输入 E2E；正式设计内容与修订号保持不变。

## 项目结构

```
data/                  默认数据根，可整体替换为 ALLOYFRAME_DATA_DIR
  catalog/
    profiles.json      共享型材库：截面、槽口、米重、单价
    accessories.json   共享配件库：角码、T 螺母、脚杯、端盖…
  designs/
    standing-desk.json  升降桌示例；每个 <id>.json 对应一个进行中项目
```

## 设计文件格式

`id` 须与 `<id>.json` 的文件名一致，只允许小写字母、数字和单个短横线分隔。设计、零件、meta 与配件条目拒绝未知字段；`$schema` 是可选编辑器标注，不会发起远程读取。以下仅为格式片段，完整示例见 `data/designs/standing-desk.json`；正式 JSON 需去掉 JSONC 注释。

```jsonc
{
  "id": "standing-desk",
  "name": "升降桌 · 单柱双列",
  "revision": 0,              // 省略时默认 0；Web 保存 / 改名由服务端递增
  "units": "mm",              // 全局唯一单位，不做任何换算
  "meta": {
    "heightRange": [720, 1180],
    "frameHeight": 720,       // 声明的模型顶面高度，校验整体最高点
    "loadRating": 120
  },
  "parts": [
    {
      "id": "frame-rail-front",
      "kind": "beam",         // beam | plate | column | box
      "role": "长边框",
      "profile": "4040",      // beam 必填，引用 profiles.json；其他 kind 不应填写
      "material": "6063-T5 银白阳极氧化",   // 纯标注，不影响几何
      "size": [1300, 40, 40], // 包围盒 [x,y,z]，beam 的最长边即下料长度
      "position": [0, 675, 290],           // 中心点，不是端点
      "massKg": 3.8,          // 可选：单件重量标注，覆盖估算；来源需自行核实
      "note": "框体前后主梁"
    }
  ],
  "accessories": [
    { "ref": "bracket-outer-4040", "qty": 12 }
  ]
}
```

### 三条硬约定

1. **`position` 是中心点，不是端点。** 端点语义在斜撑、非正交时会变成噩梦。
2. **beam 的 `size` 最长边就是下料长度，不做端头扣减。** 扣减在写文件时完成 —— 这样算料单是纯聚合，没有隐藏逻辑。
3. **全局 mm，3D 场景里也是 mm。** 不做 mm↔m 转换。代价是相机 `near`/`far` 必须显式放大（见 `Scene.tsx`），three 默认 `far=1000` 会把整个模型裁掉。

## 已知技术坑（都踩过了）

| 坑 | 现象 | 解决 |
|---|---|---|
| 相机裁剪面 | 页面纯白/纯背景色，模型完全不可见，且无报错 | `near`/`far` 按模型尺度算，不能留默认值 |
| `drei` 的 `<Grid>` | canvas 缓冲区锁死在 300×150 | 改用 three 原生 `gridHelper` |
| `<Environment preset>` | 拉远端 HDRI，失败时整个场景静默挂起 | 用 `<Lightformer>` 程序化生成环境贴图 |
| 金属材质发黑 | `metalness` 高但没有环境反射 | 必须有 `Environment`，否则只能靠 roughness 假扮 |
| 旋转单位 | 型材沿错误方向歪出 | `axisRotation` 返回**弧度**，不是度 |

## 数据可信度

`profiles.json` 里每条型材都有 `source` 字段：

- `supplier` — 来自供应商实测手册
- `estimate` — 来自公开资料估算

**当前所有型材数据均为 `estimate`。** 采购前必须以供应商实测手册核对米重与单价。升降柱等空心件按实心包围盒估算会严重偏重，所以 `parts[]` 支持用 `massKg` 标注单件重量覆盖估算；示例中的历史标注未经过供应商实测确认，不能据此视为已验证重量。

算料单里的价格仅供估算，不是报价。
