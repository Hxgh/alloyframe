# 铝构 · AlloyFrame

铝型材结构参数化 3D 预演与算料工作台。

以运行数据目录中的 `designs/<id>.json` 为设计数据源，实时驱动 T 槽三维截面渲染、拆解预演、物料清单（BOM / 切割单 CSV）与几何规范校验。计算引擎为纯确定性逻辑，无内置大语言模型。仓库的 `data/` 提供公开初始数据，日常项目默认保存在独立的本地目录。

## 快速开始

需要 **Node.js 22**（CI 使用 22）和 **pnpm 11.24.0**（`package.json` 已声明 `pnpm@11.24.0`）。请先安装这两个工具；使用 Corepack 的环境可启用 Corepack 并激活该版本的 pnpm。首次安装依赖需要访问包仓库。

在项目根目录执行：

```bash
node --version                  # v22.x
pnpm --version                  # 11.24.0
pnpm install --frozen-lockfile
pnpm dev                        # http://127.0.0.1:3210
```

生产模式先构建再启动，默认监听 `127.0.0.1:3000`（`PORT` 可改端口）：

```bash
pnpm build
pnpm start
```

常用检查：

```bash
pnpm typecheck                  # 类型检查
pnpm lint                       # 代码检查
pnpm test                       # 单元测试
pnpm validate                   # 校验运行数据中的全部设计（或 pnpm validate <id>）
pnpm build                      # 生产构建
```

**构建联网与遥测**：页面通过 `next/font/google` 使用 Geist 和 Geist Mono；Next.js 在构建时下载字体 CSS 和文件，无法访问字体服务时生产构建可能失败。成功构建后字体由应用自行托管，浏览器无需为它们直接请求 Google。Next.js 可能收集匿名遥测，可在运行相关命令前设置 `NEXT_TELEMETRY_DISABLED=1`，或执行 `pnpm exec next telemetry disable`。

## 核心流程

- **项目库（`/`）**：支持新建、复制、导入（文件 / JSON 文本，上限 2 MiB）、重命名与归档恢复（运行数据根目录下的 `archive/`）。
- **工作台（`/projects/<id>`）**：
  - **表单 → 应用 → 保存**：构件与项目表单修改须先点击“应用”进入 JSON 草稿；满足保存条件的合法草稿默认停止编辑 1.5 秒后自动落盘，也可切换手动保存。
  - **浏览器草稿**：未保存的 JSON 在当前浏览器同源 `localStorage` 中按项目与编辑会话备份，其他同源会话也可能发现并恢复备份；不包含尚未应用的表单输入。清除浏览器数据或存储不可用会丢失备份，且备份可能包含敏感设计，不应依赖共享浏览器或把它当作加密、历史版本或正式备份。恢复前可关闭自动保存：恢复的有效草稿满足条件时可能在 1.5 秒后自动写入正式文件。
  - **并发防护**：基于文件 SHA-256 指纹检测外部修改（HTTP 409），冲突时支持重新载入或另存副本；这不是多进程文件锁或历史备份。
  - **视图操作**：适应视图按当前装配或拆解范围居中并保持观察方向；重置视角恢复默认斜视。初次加载和窗口尺寸变化仍保留最大拆解范围，不会重置选中项与拆解比例。
  - **算料与导出**：实时汇总型材长度、估算重量与成本，支持导出设计 JSON、切割清单与完整 BOM（CSV）。
  - **可见连接件**：有安装实例的配件显示角码示意，并在“项目 → 项目配件 → 连接说明”中只读列出双方零件、备注和完整套件。实例采用世界坐标，通过高级 JSON 编辑；没有自动装配求解，修改几何不会自动重新布置连接。

## 三个典型 DIY 示例

默认运行目录首次初始化时复制以下 **40 系 I 型槽 8** 示例，项目库和新建项目模板均可使用这套方案；如已归档或删除，项目库不会自动补回：

| 示例 | 工作台入口 | 设计文件 | 连接套件 |
|---|---|---|---|
| 固定工作台 · 800×600×750mm | `/projects/workbench-i8` | [workbench-i8.json](./data/designs/workbench-i8.json) | 16 套结构件 + 4 套独立台面件 |
| 双层置物架 · 600×400×900mm | `/projects/shelf-i8` | [shelf-i8.json](./data/designs/shelf-i8.json) | 16 套结构件 + 8 套独立层板件 |
| 开放设备围框 · 600×500×600mm | `/projects/enclosure-i8` | [enclosure-i8.json](./data/designs/enclosure-i8.json) | 16 套结构件，无封板/门/联锁 |

一套结构件含 1 只二孔角码、2 颗 DIN 912 M8×16 和 2 只 I8 M8 T 螺母；板材件另含板侧木螺钉与垫片，不与结构件混计。有 `instances` 时数量须与实例数一致，套内零件不重复计料。接口、下料与连接审查见 [07 典型 DIY 示例与连接审查](./docs/07-典型DIY示例与连接审查.md)。

**兼容旧文件**：无 `instances` 的旧配件格式仍可读取、编辑与计料，不自动生成连接、不改槽型，也不迁移 `standing-desk.json`。旧升降桌仍有中横撑两端各 6mm 间隙、缺顶板/转接接口、钢柱无 T 槽、板固定缺件和端盖备注错误，详见 [05 升降桌专项](./docs/05-升降桌专项.md)。

> 示例的截面内部、角码与孔位、木板固定规格为简化示意，未取得完整供应商 CAD 或承载/抗拔验证；没有额定载荷承诺。开放围框不是安全防护罩，通过数据校验不等于可以直接制造或安全使用。

## 数据隔离与目录结构

默认数据根目录是**当前工作目录下的 `.alloyframe-data/`**；请在项目根目录执行命令。首次获取默认目录时，程序从仓库的 `data/` 复制公开的设计 Schema、`catalog/` 型材及配件库（含 Schema）和四个设计：`workbench-i8`、`shelf-i8`、`enclosure-i8`、`standing-desk`。初始化不会覆盖已有同名文件，完成后以 `.initialized` 标记；之后不会因示例被删除或归档而重新复制。只读模式也会在首次获取默认目录时执行这次初始化，因此该目录和其父目录首次仍须允许写入。

显式设置 `ALLOYFRAME_DATA_DIR`（或旧变量 `SUNMAO_DATA_DIR`）时，**获取目录不会自动初始化或填充数据**。请事先提供绝对路径和 `catalog/profiles.json`、`catalog/accessories.json`，并按需提供 `designs/`；也可自行从公开的 `data/` 复制初始数据。应用写操作按需创建项目或归档目录，但不会为显式目录复制初始文件；显式目录为空或缺少必需目录/文件时，不会回退到默认目录。`pnpm validate` 只扫描所选根目录的 `designs/`，忽略 `archive/`；空项目仅警告，校验错误返回非零状态。

```text
data/                  仓库内的公开初始化数据及 Schema，不是默认运行数据
  catalog/             公开型材库、配件库及其 Schema
  designs/             四个公开初始设计
.alloyframe-data/      默认本地运行数据（被 Git 忽略；请自行备份）
  catalog/             运行时型材库、配件库
  designs/             进行中的项目
  archive/             归档的项目（需要时创建）
docs/                  铝型材选型、槽型、连接与升降桌领域参考
src/
  app/                 Next.js 路由、页面与项目读写 API
  components/          3D 场景、算料面板与项目编辑器
  lib/                 Schema、校验、BOM、存储与测试
  scripts/validate.ts  命令行校验入口
```

`.gitignore` 只阻止未跟踪文件被自动加入版本控制，**不能移除已经跟踪的文件或清理历史**。运行数据、归档、浏览器草稿和导出文件都可能包含私密信息，请自行限制访问、备份并在共享前检查；不要将私有数据复制到公开 `data/`。更换 `ALLOYFRAME_DATA_DIR` 也不会迁移现有数据。

## 环境与部署

| 环境变量 | 说明 |
|---|---|
| `ALLOYFRAME_DATA_DIR` | 运行数据根目录的绝对路径；未设置时为当前工作目录下的 `.alloyframe-data/` |
| `ALLOYFRAME_READ_ONLY` | 设为 `1` 时禁止应用层项目写操作；不影响首次默认目录初始化，也不替代文件系统权限或访问认证 |
| `ALLOYFRAME_TRUSTED_ORIGINS` | 以逗号或空白分隔允许写入的完整 HTTP(S) Origin，例如 `https://frame.example.com`；配置仅放行来源，不提供认证 |
| `PORT` | 生产启动端口；未设置时为 `3000` |

上述 `ALLOYFRAME_*` 兼容对应的 `SUNMAO_*` 旧变量，新变量**未定义**时才回退；显式空值也会优先。旧版 `sunmao:*` 浏览器存储键可兼容读取。

**安全边界**：默认开发和生产脚本只监听本机回环地址。项目没有内置用户登录、身份认证或按用户的数据隔离；读取接口也没有鉴权。写入默认要求本机同源，受 `ALLOYFRAME_TRUSTED_ORIGINS` 与只读模式约束，但 Origin/Host 可伪造，来源检查不是认证。`next.config.ts` 的 `allowedDevOrigins` 仅控制开发资源请求，不是项目 API 的写入授权；其 `172.*.*.*` 通配范围大于私有 `172.16.0.0/12`，不要视作网络访问控制。若主动暴露到局域网或公网，必须在可信反向代理/网络层为**全部页面、读写 API 和开发资源**配置认证、授权和适当隔离，不要把默认监听改成公开地址后直接使用。只读模式也会暴露可读取的项目数据。

**单实例限制**：运行数据保存在本地文件系统，写操作只在同一进程内排队；文件指纹能发现部分外部变更，但不是跨进程/多服务器锁。不要让多个应用实例或其他写入者同时修改同一目录，外部编辑也应错开 Web 保存；部署时使用持久化目录并由使用者负责备份。若按单机部署方式打包或迁移，需同时保留公开 `data/` 初始文件供默认目录首次初始化使用。
